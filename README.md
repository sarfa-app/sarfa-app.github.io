# Сарфа — бюджет по конвертам

Личный бюджет по конвертам для iPhone (PWA). Валюта — сомони, интерфейс на русском.
Каждый пользователь заходит под своим логином и паролем и видит только свои траты.

Три механизма, ради которых всё сделано:

1. **Основной счёт не превращается в кошелёк.** Добор с основного счёта виден у категории
   («добрано с основного счёта: X смн»), а траты меньше порога (2 000 смн) подсвечиваются как
   нарушение правила. Запрета нет: предупреждение, но запись проходит.
2. **Перерасход не прячется.** Факт по категории — из всех источников сразу; трата сверх лимита
   остаётся красной в своей категории.
3. **Наличные сверяются.** «Сверить наличку по блокам» пишет разницу в «Не записано» своего
   блока, а не в обычные категории. Способ оплаты (наличка/карта) записывается у каждой траты.

## Как поставить на iPhone

1. Откройте адрес приложения в **Safari**.
2. «Поделиться» → **«На экран „Домой“»**.
3. Запускайте с иконки — откроется без адресной строки, работает и без интернета.

## Устройство

| Часть | Что используется |
|---|---|
| Интерфейс | Vite, React 18, TypeScript, Tailwind CSS 3 (поддержка Safari 14+) |
| Офлайн | PWA: manifest + service worker (Workbox), статика в кэше |
| Аккаунты и данные | Supabase: Auth (логин + пароль) и Postgres |
| Хостинг | GitHub Pages, сборка и публикация через GitHub Actions |

### Данные и безопасность

- **Пароли** хранит Supabase Auth в виде хэша bcrypt; приложение их не видит и не сохраняет.
- **Изоляция пользователей** — на уровне базы: Row Level Security в `supabase/schema.sql`
  разрешает читать и менять строку бюджета только её владельцу (`auth.uid() = user_id`).
  Даже изменённый клиент не получит чужие данные.
- **Соединение** только по HTTPS. Политика безопасности контента (CSP) в `index.html`
  разрешает скрипты только с самого сайта и сетевые запросы только к своему проекту Supabase.
- **На устройстве** — копия данных пользователя для офлайн-работы. При выходе из аккаунта
  она удаляется, так что на общем телефоне следующий человек ничего не увидит.
- Публичный ключ Supabase (publishable / anon) виден в сборке — так и задумано; защищают
  данные правила RLS. Ключ `service_role` в приложение не попадает и не нужен.
- Логин превращается в служебный адрес `логин@sarfa.local` только для Supabase Auth; писем
  не бывает. Восстановить забытый пароль нельзя — почты нет.

### Синхронизация

Состояние бюджета — один JSON-документ на пользователя (таблица `budgets`). Каждое изменение —
это действие (`src/domain/reducer.ts`): оно сразу применяется и сохраняется на устройстве, а на
сервер уходит, когда есть сеть. Версии документа считаются (`rev`); если с другого устройства
успели что-то записать, несохранённые действия переигрываются поверх свежей версии — траты с
двух телефонов не теряются.

## Настройка своего сервера Supabase

1. [supabase.com](https://supabase.com) → New project (регион Central EU — Frankfurt).
2. Authentication → Sign In / Providers → Email: включено, **Confirm email — выключить**.
3. SQL Editor → вставить `supabase/schema.sql` → Run.
4. Project Settings → API Keys: скопировать Project URL и publishable (или anon) key в
   `.env.production`:

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_KEY=sb_publishable_...
VITE_BASE=/
```

Бесплатный проект засыпает после 7 дней без запросов — его можно разбудить в панели Supabase.

## Разработка

```bash
npm install
npm test            # бизнес-правила и синхронизация (vitest)
npm run dev         # нужен .env.local с ключами Supabase
npm run build       # папка dist/ — готовая статика
```

Без своего Supabase можно запустить с локальным «сервером» в браузере (только для разработки,
в рабочую сборку не попадает):

```bash
VITE_BACKEND=mock npm run dev
```

Сквозная проверка интерфейса по критериям приёмки (Playwright):

```bash
VITE_BACKEND=mock npx vite build --outDir dist-mock
npx vite preview --outDir dist-mock --port 4173 &
node scripts/e2e.mjs путь/к/файлу-импорта.json
```

Иконки пересобираются из `assets-src/*.svg`: `npm run icons`.

## Публикация

Каждый push в `main` запускает `.github/workflows/deploy.yml`: тесты → сборка → ветка `gh-pages`.
В настройках репозитория: Settings → Pages → Source: **Deploy from a branch**, ветка
`gh-pages`, папка `/ (root)`.

## Структура

```
src/domain/    модель, расчёты ТЗ §4, действия, проверка импорта — без React
src/sync/      Supabase, локальный кэш, очередь и синхронизация
src/screens/   Месяц, Траты, История, Настройки, вход, первый запуск
src/sheets/    запись траты, сверка, фонды, закрытие месяца, карточка траты
src/ui/        шит, цифровая клавиатура, тосты, общие элементы
tests/         юнит-тесты на контрольные цифры ТЗ и синхронизацию
supabase/      схема базы и правила доступа
```
